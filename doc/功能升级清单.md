## 0. 小白怎么理解这游戏的好玩之处（股市可玩性导读）

这游戏**不是**"挂机收菜、慢慢变富"那种放置游戏。爽点来自**股市模拟的真实心跳**——行情有涨有跌，你在**有限的一局**里，靠判断和一点运气把小本金滚大。三个让你"上头"的机制：

1. **杠杆（借钱炒股）**：行情对了收益翻倍涨；行情错了亏损也翻倍。**不是稳稳增长，是赌对方向的快感**。
2. **机会窗口（踏空焦虑）**：时不时弹"暴涨窗口"，限时几秒，抓住了就起飞；**错过了这波，本局收益清零、从头再来**——这就是股市里"踏空"（涨了没上车，干瞪眼）的真实焦虑。
3. **牛来彩蛋 + 排行榜**：全屏"牛来！"爆发，加上每局结束比谁赚得多。

一句话内核：**不是养牛收利息，是在倒计时里用杠杆搏一把，冲上排行榜。错过机会？再来一局。**

> 下面这些升级，就是把这个"限时搏杀 + 冲榜"的内核真正做出来。

### 【#15 详细可行性】买入改成"1/3 三连购 + 最低范围"

**你想要的效果（复述确认）：**
- 点 1 次 = 买入"当前可买总量的 1/3"
- 连点 3 次 = 买满（全部可买量）
- 有个"最低范围"兜底（不能一次只买 0.x 份这种没意义的小单）

**现状问题：** 现在 `buyStock` / `buyCattle` 每次只买 1 份，扣 1 份的钱。想满仓得点很多下，且没有任何"建仓比例"概念。

**建议做法（纯前端，不动后端/存档）：**
1. 算"可买上限 N" = `floor(当前可动用资金 ÷ 单价)`。
   - 对局制 + 杠杆下，"可动用资金 = 现金 × 杠杆"，所以 5x 时点 1 次买的份数就是 1x 的 5 倍——天然贴近"加杠杆=放大仓位"的真实体感。
2. 点击逻辑改成：
   - 第 1 次点 → 买 `ceil(N/3)` 份（≈总量 1/3）
   - 第 2 次点 → 再买 `ceil(剩余/2)` 份
   - 第 3 次点 → 买光剩余（= 全满）
   - 这样**连点 3 次正好满仓**，单次≈1/3，符合你的设想。
3. **最低范围（你提的"最低有个范围"）：**
   - 每次点击**至少买 1 份**（N≥1 才允许点；N=0 按钮置灰显示"资金不足"）。
   - 可选再加一道"最小资金门槛"：单笔消耗 < 10 牛币时不触发（避免极小额无意义）。默认只保留"至少 1 份"即可，最稳。
4. 卡片上显示"已买 x / 可买 N"，并提示"点 3 次买满"。

**可行性结论：✅ 完全可行。** 改动只在 `buyStock`（牛股类）和 `buyCattle` 两处，加一个"本次建仓进度"的临时变量（不用存档）。和现有杠杆、机会窗口无冲突——窗口内"上车"判定照旧（点了买牛股就算上车）。

**边界 / 注意点：**
- 行情每 15 秒才变，3 次连点在同一次行情内 N 不变，`ceil/ceil/剩余` 保证正好 3 次买满；若中途行情变了，按当时 N 重算，仍是"≈3 次买满"，无 bug。
- 即时型股票（政策利好）仍是一次性，不走分批。
- 工作量：小（约 30~50 行）。收益：中（建仓手感更顺、更贴近真实）。优先级：🟠。

**🐛 2026-08-17 修复记录（原实现"连点3次买满"其实点不动）：**
- 根因两层：① `buyStock` / `updateStockCards` 用 `(bullCoins*杠杆 − stockCost)/单价` 反复扣减**已花掉**的资金，部分买入后算成负数 → 买按钮被 `disabled`、且 `buyStock` 提前 `return` "已达杠杆上限或资金不足"，第2/3次点不动；② `nextBatchQ` 在第2/3次点击时把"后续传入的剩余份数"当成 `base` 去算 `targets`，导致 `q = 1 − 2 = −1 → 0`，直接返回"已满仓"，第3次买不到。
- 修复：新增 `buyableRemaining(id,cost,lev)`，预算改为"当前现金 × 杠杆"（已花资金本就不在 `bullCoins` 里，不再减 `stockCost`）；建仓会话进行中直接返回 `buySession.base − bought`，保证连点3次必买满。`nextBatchQ` 改为**始终用 `buySession.base`** 作为 targets/上限基准（不再用后续传入的 `base` 参数）。`buyCattle` 同步改用 `buyableRemaining`。
- 验证（node 仿真复刻核心逻辑）：L=1 现金300 → 3次买3张、现金归零（全现金 all in）；L=2 → 3次买6张、负债300（2x 满仓）；L=3 → 3次买9张、负债600；L=1 现金250 → 买2张剩50（资金不足，正确提示已满仓）。整文件 node vm.Script 语法 OK。

### 【#16 杠杆逻辑为什么不对 + 怎么改】

**你的直觉是对的：现在的杠杆和真实股市不一样。** 先说清它现在到底怎么算的（基于代码）：

- **买入时**：每点 1 份，只扣现金 `cost`，记录"买入时杠杆 lev"。**它并不借钱，也不多买**——`debt`（债务）字段一直是 0。
- **结算时**：每份收益 `ret = def[行情]`，然后 `ret *= lev`（把**收益率直接乘杠杆**），再 × 持有份数。
- 也就是说：现在的"5x 杠杆"= 让那 1 份的**收益率放大 5 倍**，而不是让你**多持有 5 份**。爆仓只看"现金 ≤ 0"。

**为什么不像真实股市：**
1. 真实杠杆是**借钱扩大"持仓数量"**：你有 100，开 5x → 实际控制 500 仓位（借 400）。赚亏都因"仓位更大"而放大，不是给收益率加魔法乘数。
2. 真实杠杆**有借款、有利息、有维持保证金**：借的钱要还本金+利息；仓位跌到接近本金就"Margin Call / 强平"。
3. 现在 `debt` 一直是 0，所以你**看不到"借了多少、要还多少"**，体感上不像在炒股。

**建议做法（贴近真实的"保证金交易"模型）：**
- **买入时**：可动用资金 = 现金 × 杠杆 L。能买份数 = `floor(可动用 ÷ 单价)`。扣现金，记录**债务 = 份数×单价 − 现金**（借的部分）。
- **结算时**：每份收益 = `def[行情]`（**不再额外乘杠杆**，因为仓位本身就是放大的）。盈亏 = 份数 × `def[行情]`。
- **净值** = 现金 + 持仓市值 − 债务。
- **利息**：每个行情周期对债务收一点利息（如 0.5%/周期）——这是杠杆的真实成本，也逼你"别一直硬扛杠杆"。
- **爆仓/强平**：净值 ≤ 0 → 强制平仓、本局结束（爽点保留）；净值 < 持仓 20% 时给"追加保证金"预警。
- 这样"2x"的含义变成"我控制了 2 倍仓位"，盈亏因仓位大而被放大——和真实市场一致，债务也看得见了。

**可行性：✅ 可行，但比 #15 改动大**（要改 `buyStock` / `settleCycle`，加利息、净值计算，UI 显示债务与保证金条）。工作量：中。收益：高（杠杆从"看不懂"变"真炒股"）。优先级：🔴（你点名要改）。

> 重构后"爆仓清零重来"的爽点保留；牛来符仍可在净值临界时兜底一次。
